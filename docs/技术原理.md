# 技术原理

## Qt 翻译是怎么工作的

Lichii 的 Qt 前端用标准的 Qt Linguist 流程：

```
源码 tr("...") / .ui <string>
        │  lupdate
        ▼
   .ts (XML: context + source + translation)
        │  lrelease
        ▼
   .qm (二进制) ──► 编译进 qrc ──► :/languages/zh_CN.qm
                                        │
                     QTranslator::load() ┘
                                        ▼
              translate(context, source, disambiguation)
```

关键点：**QTranslator 用英文原文（`source`）连同 `context`、消歧注释（`comment`）做哈希查找**，不是按顺序、也不是按 ID。

## 为什么上游中文包在 Lichii 上大面积失效

1. **产品改名**：Lichii fork 后把源码里的 `About Eden` 改成 `About Lichii`、`Eden Configuration` 改成 `Lichii Configuration`……但 `dist/languages/zh_CN.ts` 里的 `<source>` 仍是 Eden 版本。source 不匹配 → 译文永不命中。
2. **新增界面**：兼容性报告、麦克风、NUP 转换、着色器预缓存、帧生成状态等 Lichii 独有面板，在旧 TS 里根本没有对应条目。
3. **翻译被关掉**：`CMakeLists.txt:75` 的 `ENABLE_QT_TRANSLATION` 默认 OFF，Release 工作流也没打开。`src/yuzu/CMakeLists.txt:293` 只有在它开启时才调用 `qt_add_translation` 并生成 `languages.qrc`。所以官方 exe 的资源里通常没有 `.qm`，语言下拉只有 `<系统>` 和 `English`。
4. **资源内嵌**：`MainWindow::LoadTranslation()` 写死 `":/languages/"`，程序目录里放文件不会被读取。

## 本项目的两层解法

### 第 1 层：重做语言包

不从旧 TS 上打补丁，而是用 **Qt 6.8.3 的 `lupdate` 从 Lichii 源码重新生成权威骨架** `lang/lichii_source.ts`（2282 条、101 个 context）。这样 context、source、`<comment>` 消歧键全部与当前二进制一致。

然后把译文按优先级合并进去：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | `(context, source)` 精确匹配 | 上游 `baseline.zh_CN.ts` |
| 2 | `source` 匹配 | context 漂移也能继承 |
| 3 | `Eden→Lichii` 归一化匹配 | 处理品牌改名，同时把译文里的 `Eden` 改成 `Lichii` |
| 4 | `translations.json` 历史词库 | Lichii 升级后旧译文不丢 |
| 5 | `additions.zh.txt` | 481 条新增文案译文 |
| 6 | `extras.zh.json` | 67 条长句补遗（按英文原文索引） |
| 7 | 留空 `type="unfinished"` | Qt 回退显示英文 |

生成时必须保留骨架里的 `<location>` / `<comment>` / `<numerushint>`：`<comment>` 是消歧键的一部分，丢掉会让 `tr("Auto", "Screenshot height option")` 这类调用查不到译文。带 `numerus="yes"` 的复数条目要用 `<numerusform>` 包译文。

### 第 2 层：让语言包可插拔

打补丁后：

```
启动 → ConfigureUi 枚举 :/languages 与 <exe目录>/languages 的 *.qm
     → 下拉出现 zh_CN
     → 用户选择 → LoadTranslation 先试 <exe目录>/languages/zh_CN.qm
                 失败再回退 :/languages/
     → installTranslator + retranslateUi（即时生效）
```

之后更新汉化 = 替换一个 `.qm` + 重启（重启是为了让下拉重新枚举目录）。

## 为什么不用别的方案

| 方案 | 问题 |
|---|---|
| 直接替换 exe 里内嵌的 qrc 资源 | 需要重建资源段，脆弱且与二进制版本强绑定 |
| 只开 `ENABLE_QT_TRANSLATION=ON` 重新编译 | 每次改译文都要完整重编译 Lichii（C++ 模拟器构建很重） |
| 用 Qt 自带 `qt_zh_CN.qm` | 只翻译 Qt 标准控件，不含 Lichii 自己的界面文字 |
| 直接改 `<source>` 让它匹配 | 会破坏与二进制里英文原文的一致性，且新增条目仍无解 |

## 验证方式

`verify_qm.py` 用 PySide6 的 `QTranslator.load()` 真正加载 `dist/zh_CN.qm`（与 Lichii 同一套 Qt 代码路径），再对代表性的 `(context, source)` 调用 `translate()`。这比只检查文件存在可靠得多。
